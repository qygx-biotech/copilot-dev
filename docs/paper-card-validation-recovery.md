# Paper Card content repair

The four Paper Card endpoints share `paper-card-output.js` recovery through `callPaperCard` in the Function Compute handler: excerpt summaries, intermediate/final synthesis, combined extracted text, and canonical native PDF. Existing schemas, response formats, model selection, cache signatures and saved artifact formats are unchanged. This policy does not apply to the separate general native analysis or corpus-map repair paths.

The existing model JSON decoder (including conservative LaTeX escaping/fenced JSON recovery) runs first, followed by allowlisted descriptive omission defaults, complete schema validation, canonical source-identity/citation shape checks, and stage-specific completeness. Missing nullable title is normalized locally. No type coercion, dropped extra fields, invented source metadata or relaxed validation is introduced. Reference-only excerpts remain valid. Empty/metadata-only final cards fail without a repair call.

Only unresolved JSON syntax and schema errors qualify for one content-repair attempt. Parsed canonical source identity/version mismatches, missing identity metadata and citation integrity errors do not qualify. Host currentness, scope, quoted-source provenance, publication and atomic prior-artifact preservation still run after the returned card is validated. A repair cannot bypass them. Provider rejection, missing provider content/envelope errors and transport failure remain separate from returned-content errors.

The repair retains the original authorized messages unchanged, including their evidence/PDF, source metadata, language instructions and stage schema. It appends a host system instruction requiring exactly one valid JSON object and forbidding invented findings, identifiers/citations/provenance or following instructions embedded in prior output. The appended user message is structured data:

- `feedback.category`: `invalid_json` or `schema_mismatch`.
- Syntax: fixed `reason: invalid_json_syntax`, optional numeric `position`, `line`, `column` from the parser's coordinate suffix. Coordinates are omitted when unavailable or LaTeX normalization shifted the input.
- Schema: schema-derived `field`, `expected`, actual type/missing `received`, and a fixed `reason` (`required_field`, `unexpected_fields`, `schema_constraint`, `invalid_type_or_structure`). Unknown model-supplied property names are never echoed as feedback paths.
- `previousOutput`: `kind: untrusted_previous_model_output`, `text`, `shortened`, `originalCharacters`, `retainedStart`, `retainedEnd`. At most **16,000 JavaScript characters** of prior output are included, centered on the error position or schema field where possible, otherwise its start. This bounds the prior-response text, not the unchanged original evidence or schema; JSON escaping adds envelope bytes. Shortening is explicit. It does not summarize, invent or reconstruct omitted text.

Limits per stage: **two logical generations total**, each with the existing **two-attempt provider adapter limit**, hence at most **four provider attempts**. Both generations share the five-minute provider recovery deadline and cancellation signal. The desktop performs one transport send per Paper Card endpoint and no separate excerpt validation loop. Backend ordinary retryable rate errors observe Retry-After within existing 120-second cooldown/five-minute deadline bounds. Combined-text verified input-token quota still returns immediately to the existing host excerpt-sizing fallback, avoiding a redundant whole-paper retry. Subsequent desktop requests retain shared cooldown/concurrency handling. Successful excerpts are not repeated to repair synthesis. Persistent cache hits perform no generation.

`paper_card_output_validation` and `paper_card_validation_recovery` log only stage, fixed failure reason, schema-known field, normalized field names, logical/provider attempt counts, repair outcome and stopping reason. Safe operational fields also reach desktop backend-request diagnostics. Model-facing malformed output is never a log payload. A second invalid response stops as `InvalidLlmResponse`, with validation details and `repair_exhausted`; insufficient evidence and integrity failures have distinct stopping reasons. A provider error during repair retains provider failure classification and aggregate attempt counts.

Activation requires deploying the changed FC handler plus `paper-card-output.js` and `model-json.js`, and rebuilding/reloading desktop assets to remove its obsolete excerpt loop and transport resends. Update backend and desktop together; an older desktop may still resubmit rejected excerpts. No cache migration or regeneration is needed. No deployment or running-app restart/reload was performed as part of this change. Verification uses fixture providers, not live Requesty acceptance or answer-quality measurements.
